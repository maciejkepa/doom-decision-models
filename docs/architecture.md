# Architecture and contracts

The browser owns the full Doom simulation, rendering, sensors, memory and scheduler. Local Node and Fabric Functions share `decision-core`. Neither executes Doom. Pixels and WAD data stay in the browser.

## Simulation and rendering

Pinned upstream is ozkl/doomgeneric `e257a09527062bfb986b6e5e0780839b6cbd5b71`, compiled with Emscripten 4.0.10. The vendor tree is unchanged and the build generates patched compilation inputs. Bridge version 9 includes bounded heading/point execution, camera interpolation, actual collision feedback and key requirements for observed locks. Corresponding source and SHA-256 hashes accompany the artifacts.

The single-thread browser host runs simulation at 35 Hz and renders separately at up to 60 Hz. A bounded accumulator accommodates ordinary foreground scheduling variance; gaps over 100 ms are discarded. Hidden tabs suspend simulation and clear inputs. No background backlog is replayed. Camera position, view height and shortest-path angle are interpolated between completed tics in renderer globals only. Physics, visibility, hit tests and snapshots never use interpolated state. Restart, teleport, death and suspension reset interpolation. No SharedArrayBuffer or worker isolation is required.

The world sprite projector explicitly skips `viewplayer->mo`. Vanilla Doom implicitly hides the view actor because it shares the camera position and falls behind the near clipping plane. An interpolated camera can lag several units behind that actor during movement, making its green/gray uniform fill the screen. Excluding only the view actor fixes this without removing other sprites, first-person weapons or interpolation.

All AI input enters the ordinary ticcmd before G_Ticker. Three native channel slots have separate sequence checks, deadlines, applied-tic acknowledgements and leases. Replacing one slot never releases another. Movement/fire expire after 650 ms; view after 750 ms; use and equipment use short pulses. Stop, restart, death, manual takeover and hidden tabs release all slots. Legacy combined commands are retained for mechanical diagnostics only.

AI forward input is 14 instead of the former 25. Retreat remains 25, while controlled strafe is 12 instead of 24 to reduce lateral bearing changes during aiming. Manual walking is unchanged. The native executor measures each tic's displacement projected onto the requested translation direction. After three acceleration tics, three successive tics with both total travel and requested-direction progress below 0.25 units end only that movement with `blocked`. Momentum reversal and sliding are not stationary collisions. Cumulative signed `progress` and `blockedTics` are reported per sequence. This releases ineffective input without choosing a rescue move or interrupting view/fire. It is not a collision-free navigation guarantee.

## Observations and model boundaries

Schema 4 assigns a stable episode/tic observation ID and records native capture time using the browser monotonic clock. Snapshot JSON is copied from a bounded native buffer after a completed tic. It includes each channel's current sequence, activity, remaining lease, target heading and termination reason.

At most 12 enemies/items pass both a forward 90-degree FOV and engine line-of-sight. Objects sort by distance with stable-ID tie breaks and report truncation. Enemy HP, hidden map geometry, secrets and exit functions are not disclosed. Eight local rays report traversability up to 256 units. Each keeps its center `distance` and adds `bodyDistance`, the minimum of center and four player-box corner traces. These geometry probes account for walls, opening height and step limits without invoking pickup side effects or revealing hidden actors. At most eight nearby visible surfaces report use-ray alignment, opening/closing, passability and actual use feedback. Key requirements are classified from visible usable linedefs after the same visibility filter, before use. This is a semantic simulation sensor, not texture recognition. Cards/skulls use the native six-slot inventory order, with either matching color accepted. Hidden/secret surfaces and unseen keys remain undisclosed.

`KeyMemory` retains at most 16 observed lock positions and 12 observed key positions, reconstructed from snapshot bearing and distance. The model sees last-seen time and current relative direction, explicitly distinguishing a current visible key from an old clue. Inventory changes satisfy remembered requirements and clear that color's key clues. Episode/map changes reset memory. Schema 4 adds optional `knownLocks` and `knownKeys` fields so older exports remain readable. The model receives named color inventory and missing-color facts, and can select a visible `face_key_ID` point. The executor performs that selected point turn without selecting targets or searching locally. Missing-key use is still rejected and no automated route is introduced.

Exploration memory describes visited 128-unit cells, observed transitions, six recent movement effects, blocked displacement, turning without travel, heading visits, and four recently seen enemies' last-known bearings. It never reads hidden current positions or selects a maneuver. Enemy memory expires after 175 tics.

## Decision pipeline

Catalog/prompt `tactics-9` makes one typed Foundry question per request: movement, view or action. The backend creates the prompt and allowed choices. The browser supplies no arbitrary prompt, credentials or endpoint. It reads `answers[channel].choice` and only verified probability fields. Missing metadata stays null.

The prompt exposes factual body clearances, actual failed translation, remaining turn, loaded ranged weapon, nearest visible enemy and recent damage. It asks the model to preserve distance with strafe/retreat while firing, search after failed motion or unseen damage, and hold translation during a large search turn. Every translation and scan remains available. There is no locally recommended action, hidden route or automatic evasive controller. Native feedback also catches collisions that occur later than the first movement-history sample. Repeated snapshots do not count the same failed sequence twice.

Requests and responses carry channel, sequence, request ID, observation ID, episode and controller epoch. `DecisionTransport.decide` is shared by local HTTP and Fabric. Responses contain one choice, its target heading and optional snapshot point, optional scores/usage and redacted diagnostics. Unknown choices, mismatched correlation or altered headings/points are rejected. Snapshot coordinates are reconstructed from the observed bearing/distance and quantized to 0.001 world units for deterministic transport comparison. Schema 4 adds optional point fields to inputs/responses, and traces add requested point/current required heading. Releases still require matching client, API and WASM artifacts. Old exported sessions remain inspectable as historical JSON, not executable inputs.

The view catalog includes relative scan increments and explicit `face_enemy_ID` / `face_surface_ID` choices. Scans retain an absolute snapshot heading, deduct completed travel and do not reverse to replay a passed angle. Explicit target choices instead retain a fixed world point from the selected observation. Each tic the executor recomputes the required bearing from the player's current position to that unchanged point. Its point servo uses observed own displacement as bearing-rate feedforward and a 12/s angular error term when the required bearing is changing. Stationary bearings retain the original braking profile rather than adding an asymptotic settling delay. Speed and acceleration remain limited to 90 degrees/s and 720 degrees/s². A point lease stays active for up to 750 ms even when aligned, so subsequent strafe does not lose its aiming reference. A point closer than 16 units ends the lease rather than producing a singular bearing. Restart resets own-motion measurements, and jumps over 128 units are excluded from feedforward.

`continue_turn` preserves the selected point or heading. The executor never reads live enemy coordinates or selects a replacement target. If an enemy moves or disappears, its recorded point does not move. Decision-1 must select the next correction. Renewing the same point does not reset the own-motion estimate or interpret a newly selected target position as target velocity. Stationary alignment tolerance remains 0.5 degrees. Trace angular error is measured against the direction currently required for the same point, rather than incorrectly comparing it with an old heading after translation.

Three asynchronous lanes each permit one outstanding request and a minimum 500 ms between starts. Starts are staggered, limited to six per sliding second and three outstanding overall. Busy lanes skip opportunities without queuing stale observations. TTL is 500 ms from snapshot capture; path timeout is 1200 ms. Local HTTP can abort its upstream fetch; Fabric SDK cancellation cannot guarantee cancellation of work already running remotely. Epoch/sequence checks reject late results in both transports. Cancellation never guarantees reversal of inference cost.

Timeouts and malformed decisions release only their lane. Authentication/configuration failures stop AI. HTTP 429 applies common backoff; other transient errors back off their lane, with a six-failure stop. Retries capture new observations. Use and wait require stationary movement/view, checked again at the native boundary. An active point lease is compatible with interaction only when aligned within 0.5 degrees and producing no angular input. Use rechecks the actual use ray and key inventory. Accepted use advances the epoch and cancels pre-activation requests, then obtains new observations immediately. An old movement choice cannot restart translation after the door was used.

The catalog only offers `use` for a ready/closed surface in the actual use ray with activation available and no known missing key. The browser rechecks this against current state before native submission. Opening/open/closing doors and activated switches do not offer another use. This prevents a repeated model use from toggling an opening door closed and repeatedly invalidating movement requests.

An accepted wait similarly invalidates pending work and pauses request lanes for at most 600 ms. While waiting for a known activated/opening door, the controller polls fresh native state every 35 ms and wakes lanes as soon as that same door in the same episode becomes passable. It reserves the first eligible request for movement, including a short wait for that lane's 500 ms rate deadline instead of spending the shared request slot on view/action. A wait that becomes unnecessary during HTTP is rejected without advancing the epoch or cancelling pending movement. Unrelated doors cannot wake the wait. Switches and unresolved/missing door observations retain the bounded timer. Death and episode changes invalidate the wait. This changes observation/request timing only, and Decision-1 still chooses whether and where to move. A newly passable door also clears its fresh-activation waiting fact in the prompt.

## UI, traces and measurements

Each channel retains its last available probabilities while requests are pending or omit scores. Keyed rows remain mounted for unchanged options. Bar updates animate transforms rather than layout-affecting widths. Each group shows sample age, request state and p50/p95. Current native input activity is distinct from the model's latest proposal. History rows are memoized and change with history, not each observation poll.

The bounded 1000-record trace retains observations, choices, application tics, source/requested/executed headings, angular error and termination reason. Native input state updates active execution records until termination or replacement. JSON/JSONL exports include contract/catalog/prompt/engine versions, IWAD hash, parameters, outcomes and performance. Rendering reports FPS, TPS, latest render cost and p95 frame intervals/render costs over 240 frames. Exports also report p95 simulation work per rendered frame and the latest native snapshot cost to distinguish sensor work from rendering and host scheduling. Per-channel expired lease counts and idle milliseconds are sampled at simulation tics, reset on restart, and distinguish lease gaps from explicit hold/release.

## Access and packaging

Node binds loopback, checks Host/Origin, caps JSON at 64 KiB and limits inference to three concurrent calls and six starts per rolling second. Fabric uses the same instance limiter, protected hosting and application authentication. Its instance limits are not a distributed quota; restrict access and configure Foundry quotas. Credentials remain server-side. Fabric invocation and WASM/data packages remain separate. Remote Fabric deployment is unverified until its own acceptance test succeeds.
